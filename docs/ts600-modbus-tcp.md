# TS600 系列 Modbus TCP 通讯与地址说明

> 适用对象：现场工程师 / 上位机调试人员
> 适用 HMI：hmi-designer **v2**（`hmi-designer-v2`）——PLC 设置里**协议下拉选「TS600 TCP」**（内部字段 `addr_profile = ts600-modbus-tcp`，只在连接配置/接口里出现，界面上不用管）
> 手册依据：TS600 系列 PLC 手册 **7.7.3.2「地址绑定表」**（元件 ↔ 协议地址）
> 实现依据：`server/addr_model.py`（地址解析）、`server/modbus.py`（链路/编解码）、`js/core/addrMap.js`（前端地址提示）
> 本文所有偏移、字序、报文样例均按上述代码的**实际行为**现场核算（核算方法见附录 C），未采用"按手册推断"。

## 1. 通讯参数

TS600 作为 **Modbus TCP 从站（Server）**，HMI 作为主站（Client）连它。

| 项目 | 取值 | 说明 |
| --- | --- | --- |
| 协议 | HMI「协议」下拉选 **TS600 TCP**；总线上是标准 Modbus TCP 从站 | 同一下拉还有「Modbus TCP」（INVT 写法）和「OPC UA」。选错协议时 `D100` 这类地址会变内部变量（见 7.3） |
| 端口 | **502** | TS600 侧从站端口默认 502，HMI 连接设置里填同一端口 |
| 站号 Unit ID | **1** | HMI 默认 1；必须与 PLC 侧从站站号一致，否则 HMI 报"站号不匹配" |
| 地址基准 | **0 偏移（无 1 偏移）** | 元件编号 n 直接就是协议偏移：D0 → 保持寄存器 0，D100 → 100，M0 → 线圈 0，X0 → 离散输入 40960（见第 3 节） |
| 连接方式 | TCP 长连接 | 一次一问一答；事务号每帧 +1，响应原样带回 |
| 单帧上限 | 读寄存器 ≤ 125 个 / 读位 ≤ 2000 个 | HMI 与协议都按此限制，超了 HMI 直接报错不发帧 |
| 16 位寄存器字节序 | 高字节在前（大端） | Modbus 标准；与字序设置无关 |
| 32/64 位跨寄存器字序 | `abcd` / `cdab` / `badc` / `dcba` 四选一 | 默认 **cdab（低字在前）**，见第 8 节 |
| 掉电保持 | M0~M999、S0~S999 **掉电不保存** | 见 3.6 节 |
| 轮询周期 | 默认 200 ms，最小可填 **1 ms** | 1 ms = 「尽可能快」：一轮读完立刻读下一轮，实际周期 = 读一轮的耗时（现场实测单帧往返 1.5~2 ms、一页 8 块约 15 ms）；TS600 做从站时建议 ≥ 100 ms，别低于 50 ms（本机实测 1 ms 也能跑，但会增加 PLC 负载） |

> **最常见的三个坑**：① 站号不对；② 把 32 位变量（REAL/DINT）放成单字地址；③ 32 位字序与 PLC 侧不一致（数值正确但读出来是天文数字）。分别见 3.2、3.3、第 8 节。

## 2. 报文格式（MBAP + PDU）

### 2.1 MBAP 头（7 字节）

MSB 在前（big-endian），所有多字节字段都是"高字节在前"。

| 偏移 | 长度 | 字段 | 含义 | 样例值 |
| --- | --- | --- | --- | --- |
| 0 | 2 | 事务号 Transaction ID | 主站每帧 +1，从站原样返回；HMI 用它配对响应 | `00 01` |
| 2 | 2 | 协议号 Protocol ID | 固定 **0x0000** | `00 00` |
| 4 | 2 | 长度 Length | 其后的字节数 = **1（站号）+ PDU 字节数** | `00 06` |
| 6 | 1 | 站号 Unit ID | 默认 1，与连接设置一致 | `01` |
| 7… | n | PDU | 功能码 + 数据（见 2.2、2.4） | `03 00 64 00 01` |

> 长度字段是 MBAP 自己的长度，**不含**开头 6 字节（事务号+协议号+长度）。

### 2.2 PDU 结构

**读类**

| 功能码 | 请求 PDU | 响应 PDU |
| --- | --- | --- |
| 01 读线圈 | 功能码(1) + 起始地址(2) + 位数量(2) | 功能码(1) + 字节数(1) + 位数据(NB) |
| 02 读离散输入 | 功能码(1) + 起始地址(2) + 位数量(2) | 功能码(1) + 字节数(1) + 位数据(NB) |
| 03 读保持寄存器 | 功能码(1) + 起始地址(2) + 寄存器数(2) | 功能码(1) + 字节数(1,=2N) + 寄存器值(2N) |
| 04 读输入寄存器 | 功能码(1) + 起始地址(2) + 寄存器数(2) | 功能码(1) + 字节数(1,=2N) + 寄存器值(2N) |

**写类**

| 功能码 | 请求 PDU | 响应 PDU |
| --- | --- | --- |
| 05 写单个线圈 | 功能码(1) + 输出地址(2) + 输出值(2，FF00=ON / 0000=OFF) | **原样回显请求 PDU** |
| 06 写单个寄存器 | 功能码(1) + 寄存器地址(2) + 寄存器值(2) | **原样回显请求 PDU** |
| 0F 写多个线圈 | 功能码(1) + 起始地址(2) + 位数量(2) + 字节数(1) + 位数据(NB) | 功能码(1) + 起始地址(2) + 位数量(2) |
| 10 写多个寄存器 | 功能码(1) + 起始地址(2) + 寄存器数(2) + 字节数(1,=2N) + 寄存器值(2N) | 功能码(1) + 起始地址(2) + 寄存器数(2) |

**位打包规则（01/02/0F）**：请求里的第 1 个位 = 数据区第 1 个字节的 **bit0（最低位）**，第 2 个位 = bit1 …… 第 9 个位 = 第 2 个字节 bit0。所以"读 M0~M15，首字节 bit0=M0、bit4=M4；第二字节 bit0=M8、bit2=M10"。

### 2.3 一个完整帧逐字节看

例：读 D100（D100 当前值 1000 = 0x03E8），站号 1，事务号 1。

**请求（12 字节）**

```
00 01 | 00 00 | 00 06 | 01 | 03 | 00 64 | 00 01
MBAP 7 字节                    PDU 5 字节
```

| 字节 | 值 | 含义 |
| --- | --- | --- |
| 0-1 | `00 01` | 事务号 1 |
| 2-3 | `00 00` | 协议号 0（Modbus） |
| 4-5 | `00 06` | 长度 6 = 1（站号）+ 5（PDU） |
| 6 | `01` | 站号 1 |
| 7 | `03` | 功能码 03（读保持寄存器） |
| 8-9 | `00 64` | 起始地址 0x0064 = 100 → **D100** |
| 10-11 | `00 01` | 读 1 个寄存器 |

**响应（11 字节）**

```
00 01 | 00 00 | 00 05 | 01 | 03 | 02 | 03 E8
```

| 字节 | 值 | 含义 |
| --- | --- | --- |
| 0-1 | `00 01` | 事务号（与请求一致） |
| 2-3 | `00 00` | 协议号 |
| 4-5 | `00 05` | 长度 5 = 1（站号）+ 4（PDU：03 02 03E8） |
| 6 | `01` | 站号 |
| 7 | `03` | 功能码 |
| 8 | `02` | 字节数 = 2×寄存器数 |
| 9-10 | `03 E8` | D100 = 0x03E8 = 1000（高字节在前） |

### 2.4 长度字段怎么算（自查用）

| 报文 | 长度字段 = 1 + PDU 字节数 |
| --- | --- |
| 读寄存器请求（03/04） | 6 |
| 读位请求（01/02） | 6 |
| 读寄存器响应（N 个寄存器） | 1 + 2 + 2N = 3 + 2N |
| 读位响应（N 个位，NB=ceil(N/8)） | 1 + 2 + NB = 3 + NB |
| 写单个（05/06）请求与响应 | 6 |
| 写多个线圈（0F）请求 N 位 | 7 + NB |
| 写多个线圈（0F）响应 | 6 |
| 写多个寄存器（10）请求 N 个寄存器 | 7 + 2N |
| 写多个寄存器（10）响应 | 6 |
| 异常响应 | 3（站号 1 + 功能码 1 + 异常码 1） |

对照本文样例：读 1 寄存器响应长度 `00 05`（3+2×1=5）✓；读 2 寄存器 `00 07`（3+4=7）✓；读 16 位（2 字节）`00 05`（3+2=5）✓；读 8 位（1 字节）`00 04`（3+1=4）✓；写多个线圈 16 位 `00 09`（7+2=9）✓；写 2 寄存器 `00 0B`（7+4=11）✓；异常 `00 03` ✓。

## 3. 元件 ↔ 协议地址绑定表

两张表：**位元件**（走 01/02/05/0F）和**字元件**（走 03/06/16）。同一段协议数值（例如 0x0000）在位表和字表里各有一套，互不冲突——M0 是线圈 0，D0 是保持寄存器 0。

### 3.1 位元件（BOOL → 线圈/离散输入）

| 元件 | 编号范围 | 协议地址（十六进制） | 协议地址（十进制） | 功能码 | 读写 | 编号进制 | 备注 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| M 辅助继电器 | M0~M32767 | 0x0000~0x7FFF | 0~32767 | 01 / 05 / 0F | 可读写 | 十进制 | M0~M999 **掉电不保存** |
| S 特殊继电器 | S0~S4095 | 0x8000~0x8FFF | 32768~36863 | 01 / 05 / 0F | 可读写 | 十进制 | S0~S999 **掉电不保存** |
| X 输入 | X0~X1777 | 0xA000~0xA3FF | 40960~41983 | 01 / 02 | **只读** | **八进制** | HMI 统一用 02（离散输入）读；写会被拒 |
| Y 输出 | Y0~Y1777 | 0xB000~0xB3FF | 45056~46079 | 01 / 05 / 0F | 可读写 | **八进制** | HMI 里 Y10 = 八进制，即十进制 8 |
| T 定时器触点 | T0~T399 | 0xC000~0xC18F | 49152~49551 | 01 / 05 / 0F | 可读写 | 十进制 | 与 T 的"当前值字元件"是两套地址 |
| C 计数器触点 | C0~C255 | 0xC200~0xC2FF | 49664~49919 | 01 / 05 / 0F | 可读写 | 十进制 | 与 C 的"当前值字元件"是两套地址 |

> 手册写明 X 支持 01/02 两种读法；本 HMI 把 X 一律解析到**离散输入区**、用 02 读，写 X 在 HMI 层直接拦下（不会发帧）。

### 3.2 字元件（数值 → 保持寄存器）

| 元件 | 编号范围 | 协议地址（十六进制） | 协议地址（十进制） | 每个元件占 | 功能码 | 适用变量类型 |
| --- | --- | --- | --- | --- | --- | --- |
| D 数据寄存器 | D0~D32767 | 0x0000~0x7FFF | 0~32767 | 1 寄存器（16 位） | 03 / 06 / 16 | int/uint/dword/time/dint/udint/real/lreal/字符串（多字类型占相邻 2/4/n 个寄存器） |
| R 扩展寄存器 | R0~R16383 | 0x8000~0xBFFF | 32768~49151 | 1 寄存器（16 位） | 03 / 06 / 16 | 同上 |
| T 定时器当前值 | T0~T399 | 0xE000~0xE18F | 57344~57743 | 1 寄存器（16 位） | 03 / 06 / 16 | **只能 int/uint**（16 位）；时基：T0~T199=100ms，T200~T299=10ms，T300~T399=1ms |
| C 计数器当前值（16 位段） | C0~C199 | 0xE200~0xE2C7 | 57856~58055 | 1 寄存器（16 位） | 03 / 06 / 16 | **只能 int/uint** |
| C 计数器当前值（32 位段） | C200~C255 | 0xE2C8~0xE337 | 58056~58167 | **2 寄存器 / 元件** | 03 / 16 | **只能 dint/udint/real**；只能偶数个字读写，HMI 用 FC16 一次写 2 字 |
| Z 变址/扩展寄存器 | Z0~Z15 | 0xE400~0xE40F | 58368~58383 | 1 寄存器（16 位） | 03 / 06 / 16 | int/uint 等单字类型 |

补充说明：

- **R16384~R32767 未映射到协议地址**，HMI 里直接报错，不能用。
- 多字变量（REAL/DINT/lreal/字符串）占用**相邻寄存器**：例如 `D200` + `real` 占 D200~D201（协议 200~201），`C200` + `dint` 占协议 58056~58057。**多字变量别压着元件区末地址放**：如 `D32767` 放 REAL 会被 HMI 直接拒绝（"超出元件区末地址"）；R 区末（R16383 附近）放多字变量会跨出 R 区、读到未映射地址，一定要留出 1 个字的余量。
- FC06（写单个寄存器）只能写 1 个寄存器，写 32 位变量请用 FC16（HMI 自动用）。

### 3.3 T / C 是"双身份"元件

同一个编号既是位元件又是字元件，HMI 按**变量类型**自动选：

| 地址写法 | 变量类型 | HMI 解析为 | 协议地址 | 读写走 |
| --- | --- | --- | --- | --- |
| `T5` | bool | 定时器触点（线圈） | 0xC005 = 49157 | 01 / 05 |
| `T5` | int / uint | 定时器当前值（字） | 0xE005 = 57349 | 03 / 06 |
| `C0` | bool | 计数器触点（线圈） | 0xC200 = 49664 | 01 / 05 |
| `C0` | int / uint | 计数器当前值（16 位字） | 0xE200 = 57856 | 03 / 06 |
| `C200` | dint / udint / real | 32 位计数器当前值（双字） | 0xE2C8~0xE2C9 = 58056~58057 | 03 / 16 |

### 3.4 X / Y 是八进制编号（最容易算错）

编号按**八进制**书写，协议偏移 = 区基址 + 八进制转十进制。编号里**不能出现 8 和 9**。

| 写法（八进制） | 十进制 | X 协议地址 | Y 协议地址 |
| --- | --- | --- | --- |
| X0 / Y0 | 0 | 0xA000（40960） | 0xB000（45056） |
| X7 / Y7 | 7 | 0xA007（40967） | 0xB007（45063） |
| X10 / Y10 | 8 | 0xA008（40968） | **0xB008（45064）** |
| X17 / Y17 | 15 | **0xA00F（40975）** | 0xB00F（45071） |
| X100 / Y100 | 64 | 0xA040（41024） | 0xB040（45088） |
| X1777 / Y1777 | 1023 | 0xA3FF（41983） | 0xB3FF（46079） |

- 合法上限：X1777 / Y1777（八进制），即十进制 1023；X2000 / Y2000 报"编号超出范围 0~1777（八进制）"。
- `X8`、`X9`、`Y19` 这类写法 HMI 直接报错（8/9 不是八进制数字）。
- 想确认自己算得对不对：HMI 地址列填 `X17`，把鼠标停在变量上/看状态栏提示，或用附录 C 的 python 一行命令打印 `offset`。

### 3.5 同一地址在"位/字"两套空间里的对照

| 想访问 | 位元件写法（01/02/05/0F） | 字元件写法（03/06/16） |
| --- | --- | --- |
| 第 0 点 | `M0` → 线圈 0x0000 | `D0` → 保持寄存器 0x0000 |
| 低位段重复 | `S0` → 线圈 0x8000 | `R0` → 保持寄存器 0x8000 |
| 输入段 | `X0` → 离散输入 0xA000 | （0xA000~0xA3FF 在字区未映射） |
| 输出段 | `Y0` → 线圈 0xB000 | （0xB000~0xB3FF 在字区未映射） |
| 定时/计数 | `T0`/`C0` → 线圈 0xC000/0xC200 | `T0`/`C0` → 0xE000/0xE200 |

### 3.6 掉电保持

- 手册明确：**M0~M999、S0~S999 掉电不保存**。需要断电保留的中间量放 M1000 以上、D/R 区，或确认 PLC 的保持设置。
- D/R/Z/C 等字元件的保持行为取决于 PLC 电池/保持区设置，按现场 PLC 配置为准。
- 配方、报警值这类不能丢的数据不要放 M0~M999/S0~S999。

## 4. 功能码矩阵与逐条样例

站号 1、协议号 0，事务号从 1 开始递增（下样例事务号各不相同，方便对照）。**请求 → 响应**。

### 4.1 FC01 读线圈（读 M100~M107，其中 M100、M102 为 ON）

```
请求  00 0F 00 00 00 06 01 01 00 64 00 08      ; 起点线圈 0x0064=100(M100)，读 8 位
响应  00 0F 00 00 00 04 01 01 01 05            ; 1 字节数据 0x05 = 0000 0101 → M100、M102 ON
```

### 4.2 FC02 读离散输入（读 X0 单点，X0=ON）

```
请求  00 10 00 00 00 06 01 02 A0 00 00 01      ; 离散输入 0xA000=40960 = X0
响应  00 10 00 00 00 04 01 02 01 01            ; bit0=1 → X0 ON
```

### 4.3 FC03 读保持寄存器（读 R100=0x1234）

```
请求  00 11 00 00 00 06 01 03 80 64 00 01      ; 0x8064=32868 = R100
响应  00 11 00 00 00 05 01 03 02 12 34         ; R100 = 0x1234 = 4660
```

### 4.4 FC04 读输入寄存器（格式样例）

TS600 的地址绑定表**没有给输入寄存器区**映射（数值都归保持寄存器/线圈），所以 HMI 正常不发 04。另：TS600 协议下 `%IW5` 这类输入区写法**不通讯**（按内部变量处理，见 7.3），所以也不会发 04。这一节只作为报文格式对照/用调试助手时的参考：

```
请求  00 0E 00 00 00 06 01 04 00 00 00 01      ; 输入寄存器 0，读 1 个
响应  00 0E 00 00 00 05 01 04 02 00 00         ; 值 0x0000
```

### 4.5 FC05 写单个线圈（写 S10=ON）

```
请求  00 12 00 00 00 06 01 05 80 0A FF 00      ; 线圈 0x800A=32778 = S10，FF00=ON
响应  00 12 00 00 00 06 01 05 80 0A FF 00      ; 原样回显
```

### 4.6 FC06 写单个寄存器（写 Z3=5）

```
请求  00 13 00 00 00 06 01 06 E4 03 00 05      ; 寄存器 0xE403=58371 = Z3，值 5
响应  00 13 00 00 00 06 01 06 E4 03 00 05      ; 原样回显
```

### 4.7 FC0F 写多个线圈（一次写 M0~M15，M0、M10 ON）

```
请求  00 0D 00 00 00 09 01 0F 00 00 00 10 02 01 04   ; 起点 0，16 位，2 字节数据 01 04
响应  00 0D 00 00 00 06 01 0F 00 00 00 10            ; 回显起点+数量
```

数据 `01 04`：第一字节 0x01 → bit0=M0 ON；第二字节 0x04 → bit2=M10 ON。

### 4.8 FC10 写多个寄存器（写 REAL 12.5 到 D200，字序 cdab）

```
请求  00 05 00 00 00 0B 01 10 00 C8 00 02 04 00 00 41 48
      ; 0x00C8=200 = D200，写 2 个寄存器，4 字节数据 00 00 41 48
响应  00 05 00 00 00 06 01 10 00 C8 00 02            ; 回显起点+数量
```

12.5 的 IEEE754 是 0x41480000；cdab（默认）拆成两个字 `0x0000`、`0x4148`，按寄存器顺序发 `00 00`、`41 48`。若字序为 abcd，则发 `41 48 00 00`（见第 8 节）。

## 5. 现场读写样例（照着发就能验证）

> 前提：站号 1、端口 502、HMI 连接正常。任何帧发错都会得到第 6 节讲的异常响应。
> 建议先用「读 D100」验证链路，再验证位、双字。

### 5.1 读 D100（单寄存器）

```
请求  00 01 00 00 00 06 01 03 00 64 00 01
响应  00 01 00 00 00 05 01 03 02 03 E8     ; D100 = 1000
```

### 5.2 读 D100~D101 双字（REAL 12.5，两种字序）

```
字序 abcd（高字在前）：
请求  00 02 00 00 00 06 01 03 00 64 00 02
响应  00 02 00 00 00 07 01 03 04 41 48 00 00

字序 cdab（低字在前，默认）：
请求  00 03 00 00 00 06 01 03 00 64 00 02
响应  00 03 00 00 00 07 01 03 04 00 00 41 48
```

两帧读的是同一地址，只有字序不同 → 数据排列不同，解码结果都是 12.5。**数值读出来不对时先看这里。**

### 5.3 写 D100 = 1000（FC06 单字）

```
请求  00 04 00 00 00 06 01 06 00 64 03 E8
响应  00 04 00 00 00 06 01 06 00 64 03 E8     ; 原样回显即成功
```

### 5.4 写 REAL 12.5 到 D200（FC16 双字，cdab）

```
请求  00 05 00 00 00 0B 01 10 00 C8 00 02 04 00 00 41 48
响应  00 05 00 00 00 06 01 10 00 C8 00 02
```

写完后按 5.2 的方式读 D200~D201 校验。

### 5.5 读 M0~M15（首字节 bit0 = M0）

```
请求  00 06 00 00 00 06 01 01 00 00 00 10
响应  00 06 00 00 00 05 01 01 02 01 04        ; M0、M10 ON
```

### 5.6 写 M10 = ON（FC05，值 FF00）

```
请求  00 07 00 00 00 06 01 05 00 0A FF 00     ; 0x000A=10 = M10
响应  00 07 00 00 00 06 01 05 00 0A FF 00     ; 回显即成功
```

### 5.7 读 X0~X17（八进制，16 点）

```
请求  00 08 00 00 00 06 01 02 A0 00 00 10     ; 从 0xA000 起读 16 点：X0~X17(八进制)
响应  00 08 00 00 00 05 01 02 02 01 80        ; X0 ON；X17=十进制15 → 第二字节 bit7
```

注意：`X17` 的"17"是八进制，对应第 15 位，所以落在第二个字节的 bit7（0x80）。

### 5.8 写 Y10 = ON（FC05）

```
请求  00 09 00 00 00 06 01 05 B0 08 FF 00     ; 0xB008=45064 = Y10（八进制 10 = 十进制 8）
响应  00 09 00 00 00 06 01 05 B0 08 FF 00
```

### 5.9 读 C200 双字（32 位计数器，两种字序）

```
字序 abcd：请求 00 0A 00 00 00 06 01 03 E2 C8 00 02
          响应 00 0A 00 00 00 07 01 03 04 00 01 86 A0   ; 100000 = 0x000186A0

字序 cdab：请求 00 0B 00 00 00 06 01 03 E2 C8 00 02
          响应 00 0B 00 00 00 07 01 03 04 86 A0 00 01
```

### 5.10 写 X 被拒（HMI 层拦截 + 从站异常样例）

HMI 层（根本不发帧）：

> `X17 是输入元件，只读，写不了（TS600 的 X 输入只能读；要写请用 Y 输出/M 辅助继电器）`

如果用调试助手直接给 X 发 FC05，从站回异常响应（功能码 0x85 = 05 | 0x80，异常码 02 = 非法数据地址）：

```
请求  00 0C 00 00 00 06 01 05 A0 00 FF 00     ; 试图写 X0
响应  00 0C 00 00 00 03 01 85 02              ; 从站异常 2：非法数据地址
```

### 5.11 读 T5（同一个地址的"位/字"两种身份）

```
读 T5 当前值（int，FC03）：请求 00 14 00 00 00 06 01 03 E0 05 00 01
                         响应 00 14 00 00 00 05 01 03 02 04 D2   ; 当前值 1234
读 T5 触点（bool，FC01）：请求 00 15 00 00 00 06 01 01 C0 05 00 01
                         响应 00 15 00 00 00 04 01 01 01 01      ; 触点 ON
```

### 5.12 读未映射地址（从站异常 02）

地址绑定表最大的字地址是 Z15 = 0xE40F（58383），再往上是未映射区：

```
请求  00 16 00 00 00 06 01 03 E5 00 00 01     ; 0xE500=58624，超出绑定表 → 未映射
响应  00 16 00 00 00 03 01 83 02              ; 从站异常 2：非法数据地址
```

## 6. 异常响应与 HMI 报错对照

### 6.1 异常响应格式

从站拒绝时，功能码最高位置 1（0x03→0x83、0x05→0x85、0x10→0x90…），后跟 1 字节异常码：

| 偏移 | 长度 | 字段 |
| --- | --- | --- |
| 0-1 | 2 | 事务号（同请求） |
| 2-3 | 2 | 协议号 0 |
| 4-5 | 2 | 长度 = 3 |
| 6 | 1 | 站号 |
| 7 | 1 | 功能码 OR 0x80（如 0x83 / 0x85） |
| 8 | 1 | 异常码 |

### 6.2 TS600 常见异常码

| 码 | 手册含义 | HMI 显示 | TS600 上常见原因 |
| --- | --- | --- | --- |
| 01 | 非法功能码 | `从站异常 1：非法功能码` | 调用了 TS600 不认的功能码（如某些扩展码 0x2B） |
| 02 | 非法数据地址 | `从站异常 2：非法数据地址` | 地址落在未映射段（如 R16384+、写 X）、数量越界 |
| 03 | 非法数据值 | `从站异常 3：非法数据值` | 写线圈/寄存器数量或字节数不合法 |
| 04 | 从站设备故障 | `从站异常 4：从站设备故障` | PLC 侧异常/忙，重试或查 PLC |
| 05 | 确认（正在处理） | `从站异常 5：确认（正在处理）` | 长操作未完成 |
| 06 | 从站忙 | `从站异常 6：从站忙` | 轮询过快/PLC 忙，降低 poll_ms |
| 08 | 存储奇偶校验错 | `从站异常 8：存储奇偶校验错` | PLC 存储异常 |
| 10 / 11 | 网关路径不可用 / 网关目标无响应 | `从站异常 10/11：<上述文案>` | 经过网关/路由时后端不通 |

### 6.3 HMI 地址/类型报错文案（界面原文逐字摘录）

| 场景 | HMI 报错 |
| --- | --- |
| 写 X | `X17 是输入元件，只读，写不了（TS600 的 X 输入只能读；要写请用 Y 输出/M 辅助继电器）` |
| X/Y 编号含 8/9 | `X 是 8 进制编码的元件（手册：8 进制编码 BOOL 类型），编号里不能出现 8/9：X8` |
| X/Y 超过 1777（八进制） | `X 编号超出范围 0~1777（八进制）：X2000` |
| R 用 16384 以上 | `R16384：手册写明 R16384~R32767 没有映射到协议地址上，只能访问 R0~R16383：R16384` |
| D 越界 | `D 编号超出范围 0~32767：D32768` |
| M 越界 | `M 编号超出范围 0~32767：M32768` |
| S 越界 | `S 编号超出范围 0~4095：S4096` |
| T 越界 | `T 编号超出范围 0~399：T400` |
| C 越界 | `C 编号超出范围 0~255：C256` |
| Z 越界 | `Z 编号超出范围 0~15：Z16` |
| 位元件配数值类型 | `M 元件是位元件，只能配 bool 变量；数值请放字元件（D/R/T/C/Z）：M10` |
| X 配数值类型 | `X 元件是位元件，只能配 bool 变量；数值请放字元件（D/R/T/C/Z）：X0` |
| 字元件配 bool | `D 是字元件，bool 变量请用位元件（M/S/Y/T/C 的位地址）：D100` |
| 16 位字元件配 32 位 | `T5 是 16 位字元件（1 个寄存器），放不下32 位类型；32 位数据请放 D/R（C200~C255 是 32 位计数器）：T5` |
| 16 位字元件配字符串 | `T5 是 16 位字元件（1 个寄存器），放不下字符串类型；字符串数据请放 D/R（C200~C255 是 32 位计数器）：T5` |
| C200~C255 类型不对 | `C200 是 32 位双字计数器（2 个寄存器对应 1 个元件），变量类型要用 dint/udint/real：C200` |
| C200~C255 奇数个字 | `C200~C255 是双字元件（2 个寄存器 1 个元件），只能偶数个字读写（[4] 行、[3] 不行）：C200[3]` |
| 多字变量压区末 | `D32767 占 2 个字，超出元件区末地址 (协议 32767)：换个小一点的编号，或改用能放下的类型` |
| 位元件带 [字数] | `位元件不能带 [字数]（那是给字元件/字符串用的）：M0[2]` |
| 一段超过 125 字 | `一段最多 125 个字：D100[126]` |
| 用了 Q 元件 | `TS600 没有 Q 这类元件（位元件 M/S/X/Y/T/C，字元件 D/R/T/C/Z）：Q1` |
| 从站异常 | `从站异常 2：非法数据地址`（码表见 6.2） |
| 链路异常 | `通信失败：<具体原因>`（超时/被关闭）、`未连接` |
| 事务号/协议号/站号 | `事务号不匹配（发 5 收 6）`、`协议号异常：1`、`站号不匹配（期望 1 收到 2）` |
| 超协议上限 | `一次最多读 125 个寄存器`、`一次最多读 2000 个位` |
| 字序体检用位地址 | `字序体检只对保持寄存器/输入寄存器有意义（位地址没有字序）` |
| 地址写法与当前协议不匹配 | **不报错**：变量表地址单元格显示「内部变量」，说明 `地址 D100 不符合当前协议（TS600 TCP），按内部变量处理：不采集、不下发`（见 7.3；本次 TS600 / 三协议改动起） |

### 6.4 排查顺序

1. **连不上**：IP/端口/网线 → 换 Modbus 调试助手直连 502 → 查 PLC 从站是否使能。
2. **连上但报"从站异常 2"**：地址/数量越界（对照第 3 节），或写 X。
3. **连上但报"站号不匹配"**：连接设置里的 unit 改成 PLC 侧站号。
4. **数值对不上**：先确认变量类型与地址（是否 32 位放单字），再做「字序体检」。
5. **偶发"从站忙"/超时**：轮询周期 200ms 起，别多主站抢连。

## 7. 与 INVT 写法的差异、以及"协议选错"会怎样

V2 的 PLC 设置对话框里，「协议」是一组三选一：

| 协议下拉 | 显示文字 | 地址写法 | 适合 |
| --- | --- | --- | --- |
| `modbus` | **Modbus TCP** | INVT / Invtmatic Studio 写法（`%MW96`、`%MD48`、`%QX1.2`、`%IW5`…） | INVT 系列 PLC |
| `ts600` | **TS600 TCP** | TS600 元件写法（`D100`、`M100`、`X17`…，见第 3 节） | TS600 系列 PLC（本文） |
| `opcua` | **OPC UA** | NodeId（`ns=4;s=...`） | CODESYS 内置 OPC UA 服务器 |

选 **TS600 TCP** 之后，HMI 内部把地址模型记成 `addr_profile = ts600-modbus-tcp`——这只是连接配置里的内部字段（导出配置、看接口/日志时能见到），**界面上不用找也不用改**；地址按哪种协议解释，完全由「协议」这个下拉决定。

> 落盘口径（看配置文件/接口时对得上）：
> - 连接配置 `plc.json` 与后端 `status`：`protocol: "modbus"` + `addr_profile: "ts600-modbus-tcp"`（同一条 Modbus TCP 链路，靠 `addr_profile` 区分地址模型；`status.protocol` 也一直是 `modbus`）；
> - 工程里保存的连接设置（工程 `meta.plc`）：`protocol: "ts600"` + `addr_profile: "ts600-modbus-tcp"`；
> - 打开工程时 HMI 按 `protocol` + `addr_profile` 还原成「TS600 TCP」下拉（老工程只有 `protocol` 时按 modbus/opcua 处理）。手工改配置文件时别只改 `protocol`。

对话框标题是「**PLC 连接（Modbus TCP / TS600 TCP / OPC UA）**」；协议下拉下方有一行提示，按所选协议显示：

| 选到 | 提示行原文 |
| --- | --- |
| Modbus TCP | `INVT/CODESYS 写法（%MW/%MD/%QX…）` |
| TS600 TCP | `D/M/X/Y/S/T/C/R/Z 元件写法，不支持 %MX 字内取位` |
| OPC UA | `NodeId（ns=4;s=…）` |

### 7.1 差异对照表

| 维度 | Modbus TCP（INVT 写法） | TS600 TCP（TS600 元件写法） |
| --- | --- | --- |
| 地址写法 | `%MW96` / `%MD48` / `%QX1.2` / `%IW5`，另兼容 `HR100`、`4x0100` | **元件式**：`D100`、`M100`、`S10`、`X17`、`Y10`、`T5`、`C200`、`R100`、`Z3`；另兼容 `%MW`/`%W`/`%MD`、`HR`/`4X`、纯数字（见 7.4） |
| 位区 | 输出 `%QX`、内存 `%MX`、输入 `%IX` | M 辅助、S 特殊、X 输入、Y 输出、T/C 触点（各自独立协议段）；**没有** `%QX`/`%MX`/`%IX` 这种"位区 + 偏移"写法 |
| 字区 | 保持 `%MW`、输入 `%IW`、输出字 `%QW` | D/R/T/C/Z 元件式字区；**没有输入寄存器映射**（`%IW` 无意义） |
| `%QW` 位拼字 | `%QW` = 16 个输出位拼成一个字，走 01/05/0F（不是寄存器） | **不支持**（`%QW3` 按内部变量处理，不通讯） |
| `%MX` 字内取位（如 `%MX0.0`） | `%MX` 与 `%MW` 同一片内存，改一位要读改写 | **不支持**（TS600 没有位打包/字内取位；要位就写字元件 `M10`/`X17`/`Y10`） |
| 双字/浮点 | `%MDn` = `%MW(2n)` 低 + `%MW(2n+1)` 高，字序由连接配置 | 直接放 D/R 相邻两个寄存器（`%MDn` 也可用作 `2n` 起 2 字的兼容写法）；`C200~C255` 固定是 32 位 |
| 多字限制 | 无特殊 | C200~C255 只能偶数个字；T/C 16 位段只能 int/uint |
| X 只读/进制 | `%IX` 只读 | X 八进制、只读，HMI 用 FC02 |
| 默认地址 | `%MW0` | `D0` |
| 默认字序 | `cdab` | `cdab` |
| 功能码 | 01/02/03/04/05/06/0F/10 | 相同（04 未映射，正常不发） |

### 7.2 同一个写法在两个协议下的含义（避免混用）

| 写法 | Modbus TCP（INVT 写法） | TS600 TCP |
| --- | --- | --- |
| `D100` | **不认** → 内部变量（见 7.3） | 保持寄存器 100（0x0064） |
| `%MW100` | 保持寄存器 100 | 兼容写法，保持寄存器 100（与 D100 同址） |
| `Y10` | 不认 → 内部变量 | 线圈 0xB008 = 45064（八进制 10 = 十进制 8） |
| `X17` | 不认 → 内部变量 | 离散输入 0xA00F = 40975（八进制 17 = 十进制 15） |
| `%QX10` | 输出位 / 线圈 10 | **不支持** → 内部变量 |
| `%IW5` | 输入寄存器 5 | **不支持** → 内部变量 |
| `%QW3` | 输出字 3 = 线圈 48~63 | **不支持** → 内部变量 |
| `%M100` | 保持寄存器 100（`%M` 是 `%MW` 的缩写，**不是位**；位要写 `%MX100.0` / `%QX…`） | **不支持** → 内部变量（TS600 的 M 是位元件，`%M` 字地址与它冲突） |

> 一句话：**换协议前先看地址列写的是不是元件式**。TS600 工程里写 `%MW100` 也能跑（等价 D100），但现场可读性差，建议统一用元件写法。

### 7.3 地址写法与当前协议不匹配 = 内部变量（本次 TS600 / 三协议改动起）

变量地址的写法**不属于当前协议**时，HMI 不把它当 PLC 变量，而是自动当**内部变量**：

> 本节行为自**本次 TS600 / 三协议改动起**生效；在这个版本之前没有该语义，写法不匹配会按普通地址错误处理（升级后再看本节）。

- **不采集**：不从 PLC 读，不参与轮询；
- **不下发**：控件动作、脚本 `hmi.set` 只改 HMI 里的值，不写 PLC；
- **不报错**：不会弹"下发失败 / 地址无效"，**不标红、也不阻止保存**；
- 变量表里**地址单元格显示灰字徽标「内部变量」**，鼠标停上去（title）是：`地址 D100 不符合当前协议（TS600 TCP），按内部变量处理：不采集、不下发`（其中「地址 D100」用实际填的地址，「TS600 TCP」按当前协议换成 Modbus TCP / OPC UA）；
- 值只活在 HMI 里（与"地址留空"的内部变量同一待遇），勾上「保持」还能掉电保存。

两个"内部变量"在界面上是**分开**的，别混：

| 情况 | 地址格 | 说明 |
| --- | --- | --- |
| 地址留空 | 空地址，**不显示**「内部变量」徽标 | 正常用法，悬停有"留空=内部变量"的说明 |
| 填了地址但当前协议不认 | 灰字徽标 **「内部变量」** + 上面那条 title | 按内部变量处理，可改写法恢复通讯（见下表） |

> UI 只显示这条**统一短提示**；后端返回的详细原因（就是下面"原因原文"里带元件/协议细节的那几句）不直接展示，排障时看 `/api/plc` 的 `internal_by_addr[].note` 或程序日志。
> 变量表里**标红/警告**只有一种来源：真正解析失败的地址（`status.vars[].bad_address`，例如 `D32767` 配 real 越区、`T5` 配 real 类型不对），这些是硬错误、必须改。

哪些写法会被判成内部变量：

| 当前协议 | 变量地址写成 | 结果 |
| --- | --- | --- |
| Modbus TCP（INVT 写法） | `D100`、`M100`、`X17`（TS600 元件式） | 内部变量 |
| TS600 TCP | `%M100`、`%MB10`、`%MX0.0`、`%MX10`、`%QX10`、`%QW3`、`%QB3`、`%QD2`、`%IX17`、`%IW5`、`%IB5`、`%ID2` | 内部变量（TS600 没有字内取位/位打包/输入区地址） |
| TS600 TCP | `Q1`（TS600 没有的元件字母） | 内部变量 |
| OPC UA | `D100`、`%MW100`、`M10`、`HR10`、`100`（不是 NodeId） | 内部变量 |
| 任意 | 地址留空 | 内部变量（正常用法，不受影响） |

HMI 内部给出的原因原文（现场看提示、排障日志时对得上）：

- TS600 协议下写了不支持的 `%` 写法：
  > `TS600 没有「%MX0.0」这种写法（没有 %MX/%QX/%QW/%QB/%IX/%IW 字内取位、位打包、输入区地址）；位直接写元件位地址 M10/X17/Y10，寄存器写 D100 或 %MW100。这种变量按内部变量处理，不通讯`
- INVT 协议下写了 TS600 元件式：
  > `当前地址模型是「Invtmatic/INVT Modbus_TCP_Slave（%MW/%MD/%QX/%QW… 写法）」，不认 TS600 元件写法「D100」；在 PLC 设置里把协议改成 TS600 TCP 才会通讯，否则按内部变量处理`
- TS600 协议下写了不存在的元件字母：
  > `TS600 只有 M/S/X/Y/T/C 位元件和 D/R/T/C/Z 字元件，没有「Q1」这类写法（%MX/%QX/%QW/%QB/%IX/%IW 也没有）；这种变量按内部变量处理，不通讯：Q1`
- OPC UA 协议下写了 Modbus / TS600 写法：
  > `地址 'D100' 的写法不符合当前协议（OPC UA 要填 NodeId，如 ns=4;s=PLC_PRG.x），按内部变量处理`

让这些地址恢复通讯：

| 想访问 | 正确做法 |
| --- | --- |
| TS600 的 D100 | 协议选 **TS600 TCP**，地址写 `D100`（或 `%MW100`） |
| TS600 的 M100 | 协议选 **TS600 TCP**，地址写 `M100`（变量类型 bool） |
| TS600 的 X17 | 协议选 **TS600 TCP**，地址写 `X17`（bool，只读） |
| INVT 的 MW100 | 协议选 **Modbus TCP**，地址写 `%MW100`（`D100` 在 INVT 下不认） |
| OPC UA 的节点 | 协议选 **OPC UA**，地址写 NodeId（如 `ns=4;s=Application.PLC_PRG.count`） |

⚠ **别把"内部变量"和"报错"搞混**：只有"写法不属于当前协议"才变内部变量；"写法匹配但内容不合法"仍是硬报错（不会静默不通讯），例如：

- 元件写对了但类型不对：`M10` 配 int → `M 元件是位元件，只能配 bool 变量…`；
- 编号越界/进制错：`D32768`、`R16384`、`X8`（8/9 不是八进制数字）→ 直接报错；
- 多字变量压区末：`D32767` + real → 报"超出元件区末地址"。

上面这些原文在 6.3，改到合法为止。

- 这类"写法合法但内容非法"的变量，写值时 HMI 报的原文（变量名按实际替换）：
  > `变量 v_bad 的地址 'D32767' 无效：D32767 占 2 个字，超出元件区末地址 (协议 32767)：换个小一点的编号，或改用能放下的类型`

> **从旧 INVT 工程迁到 TS600**：`%M100` 这类地址迁过来会被当内部变量（TS600 的 M 是位元件），请改写为 `D100` 或 `%MW100`；`%QX`/`%QW`/`%MX`/`%IW` 同样要改成 `M`/`Y`/`X`/`D`/`R` 元件写法。

### 7.4 TS600 下还能用的 `%` / 兼容写法

TS600 TCP 协议认这些写法（与元件写法等价）：

> 前缀清单、示例地址和「这个写法算不算合法」的**准绳在后端接口**：`GET /api/comm/protocols`（协议目录）
> 与 `POST /api/comm/validate`（单地址校验，返回 `valid`/`code`/`writable`/`address`）。本文表格是同一套规则的
> 现场说明；接口字段、错误码（`empty`/`model`/`invalid`）与扩展方式见 [comm-arch.md](comm-arch.md)。

| 写法 | 解析为 | 例 |
| --- | --- | --- |
| `%MWn` / `%Wn` | 保持寄存器 n | `%MW100` → 100（= D100） |
| `%MDn` | 保持寄存器 2n 起、2 个字（双字索引 ×2） | `%MD100` → 200~201（= D200~D201） |
| `HRn` / `4xn` / 纯数字 | 保持寄存器 n | `HR100`、`4x0100`、`100` → 100 |
| 元件式 | 见第 3 节 | `D100`、`M100`、`X17`… |

**TS600 TCP 下不支持**（按内部变量处理，见 7.3）：`%MX`（字内取位，含 `%MX0.0`）、`%QX`、`%QW`（位拼字）、`%QB`、`%QD`、`%IX`、`%IW`、`%IB`、`%ID`、`%Mnnn`、`%MBnnn`。想要位就直接写位元件（`M10`、`X17`、`Y10`、`T5`、`C0`），想要字就写 `D100`/`%MW100`。

> 建议：TS600 工程统一用元件写法，现场对照 PLC 程序最直观；`%MW100` 只当过渡。

### 7.5 HMI 里的使用步骤

1. 打开工程 → 工具栏 **🔌 PLC**（连接设置对话框）。
2. **「协议」下拉选 TS600 TCP**（三项是：Modbus TCP / TS600 TCP / OPC UA；选错就按 7.3 变内部变量）。
3. 填 PLC 的 IP、端口 **502**、站号（默认 1，必须与 PLC 侧一致）。
4. 字序保持默认 **cdab（低字在前）**；首次接一台新 PLC 时，若 32 位变量数值明显不对，点 **「字序体检」** 确认（见 8.3）。
5. 轮询周期保持 200 ms（PLC 做从站时建议 ≥100 ms）。
6. 点 **「测试连接」**：HMI 会读默认地址 **D0**，弹窗显示 `OK，D0 = <值>` 即链路通。
7. 点 **「确定」** 保存连接配置。连接成功会先弹一个确认框，形如：
   `已连接 TS600 TCP 127.0.0.1:15020（站号 1）` / `变量 47 个，轮询周期 200ms，字序 CDAB` / `地址模型：TS600 系列（D/M/X/Y/S/T/C/R/Z 元件写法）`。
   之后状态栏**直接显示协议名 + 连接状态**（不再显示"地址模型"），格式：
   - 运行态：`TS600 TCP：在线 192.168.1.10:502（47 变量，字序 CDAB）`
   - 编辑态（还没运行/没连）：`TS600 TCP：未运行 127.0.0.1:502（47 变量）`
   - 内存模拟（未连接 PLC）：`PLC：未连接（内存模拟 · TS600 TCP）`
   鼠标停在状态栏上，还能看到「地址模型：TS600 系列（D/M/X/Y/S/T/C/R/Z 元件写法）」这类细节说明。
8. 到变量表/变量面板，地址列直接写元件地址：`D100`、`M100`、`X17`、`Y10`、`T5`、`C200`、`R100`、`Z3`；同时选对**变量类型**（bool↔位元件，int/uint↔16 位字元件，dint/udint/real↔32 位，lreal/字符串放 D 区）。
   地址一填，HMI 就在旁边给出解析结果（占几个字由类型决定），例如 real/dint 的 `D100`：`数据寄存器 D100（协议寄存器 100）　占 2 个字：寄存器 100~101`；新建变量时的占位提示是 `D100 或 100（留空 = 内部变量）`。
9. 保存工程 → 运行/刷新，值开始按 poll_ms 刷新。类型/范围写错看 6.3 的报错原文；写法与协议不匹配看 7.3 的「内部变量」标注。

## 8. 32/64 位字序（abcd / cdab / badc / dcba）

Modbus 只规定 16 位寄存器内"高字节在前"。REAL/DINT/lreal 占 2/4 个寄存器时，**两个字谁在前**由设备决定，HMI 用「字序」匹配。TS600 手册未明示 32 位字序，所以必须用实测确认。

### 8.1 四种字序的编码结果

以 REAL `12.5`（IEEE754 = 0x41480000）和 DINT `100000`（0x000186A0）为例，两个寄存器依次为：

| 字序 | HMI 下拉文案 | 含义 | 12.5 的 MW 低→高 | 100000 的 MW 低→高 |
| --- | --- | --- | --- | --- |
| `abcd` | 高字在前 ABCD（大端） | 高字放低地址 | `0x4148`, `0x0000` | `0x0001`, `0x86A0` |
| `cdab` | 低字在前 CDAB（默认） | 低字放低地址（字交换） | `0x0000`, `0x4148` | `0x86A0`, `0x0001` |
| `badc` | 高字在前 + 字节交换 BADC | 先高字、再交换字节 | `0x4841`, `0x0000` | `0x0100`, `0xA086` |
| `dcba` | 低字在前 + 字节交换 DCBA | 先低字、再交换字节 | `0x0000`, `0x4841` | `0xA086`, `0x0100` |

**16 位的 int/uint 不受字序影响**（永远是寄存器内高字节在前）；只有跨寄存器的 32/64 位（real/dint/udint/dword/lreal/lint 等）才受影响。

### 8.2 对应报文差异（读 D100~D101，值 12.5）

- abcd：响应数据 `41 48 00 00`
- cdab：响应数据 `00 00 41 48`

同一地址两种解，数值都是 12.5。若字序配错，常见现象是读出 `8.9e-41`、`-2.3e38`、`1.4e-45` 这类"不像人写的数"。

### 8.3 用「字序体检」确认

1. 连上 PLC 后打开 **🔌 PLC** 对话框。
2. 「字序体检」区域填一个**真实的双字变量地址**（如 `D200`）和类型 `real`（或 dint）。
3. 点「字序体检」：HMI 读一次该地址的 2 个寄存器，按 4 种字序各解一遍，列出候选值。
4. 看哪个候选值是"合理的物理量"（如 12.5、1000、0.85），把它对应的字序选进下拉框。
5. 「确定」保存 → 重新运行时双字/浮点变量显示正确。

> 字序体检只对保持寄存器/输入寄存器有意义；对位地址（M/X/Y…）点它会提示"位地址没有字序"。

### 8.4 建议

- **默认先留 cdab**（HMI 默认、多数国产 PLC/变频器低字在前）。数值不对再做体检。
- 同一台 PLC 上**所有 32 位地址字序一致**，不要一部分 abcd 一部分 cdab。
- 现场改字序只影响 HMI 解码，**不会改写 PLC 里的数据**，可以放心试。
- 若是带"上位机双字"设置的 TS600 型号，以 PLC 侧设置为准，并用体检结果反推。

| 变量类型 | 占几个寄存器 | 可用地址 | 示例 |

## 附录 C 文档里的地址/帧是怎么核算的（可复现）

所有偏移和样例帧都由 `server/addr_model.py` + `server/modbus.py` 现场计算（不是手推）：

```bat
cd /d C:\Users\Administrator\Desktop\hmi\hmi-designer-v2\server
set PYTHONIOENCODING=utf-8
"%LocalAppData%\Programs\Python\Python310\python.exe" -c "import addr_model as A, modbus as M; A.set_profile('ts600-modbus-tcp'); a=A.parse_address('X17', vtype='bool'); print(a.area, a.offset, a.words, a.readonly); print([hex(w) for w in M.encode_value(12.5,'real',2,'abcd')])"
```

预期输出：

```
discrete 40975 1 True
['0x4148', '0x0']
```

- `a.area`（`coil`/`discrete`/`input_reg`/`holding` 四种区域）、`a.offset`（协议地址）、`a.words`（占几个寄存器）、`a.readonly`（X 为 True）。
- 帧样例：按第 2 节格式 `struct.pack(">HHHB", tid, 0, len(pdu)+1, unit) + pdu` 组帧，再逐字节核对 2.4 的长度公式；文档中 **23 组请求/响应帧（46 帧）** 均已按此校验过长度自洽（长度 = 站号 1 + PDU 字节数），可直接粘进 Modbus 调试助手复现。

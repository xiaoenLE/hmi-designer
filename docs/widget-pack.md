# 控件包（.hmiw.json）：把控件导出去给别人用

现场要的是「**别人做好的控件我能不能也用**」。控件包就是这件事：选中画面上的一个（或一组）控件 →
导出一个 `.hmiw.json` 文件 → 发给别人 → 他在自己的工程里「导入控件包…」，控件就摆到他当前页上了。

## 怎么用

| 干什么 | 在哪点 |
|---|---|
| 导出选中控件 | 画布上选中控件 → **右键 → 「导出为控件包…（给别人用）」**（多选时是「导出这 N 个控件」） |
| 导出单个控件 | 左区「清单」面板 → 那一行右键 → 「导出为控件包…」 |
| 导入 | **画布空白处右键 → 「导入控件包…（.hmiw.json）」** → 选文件 |

导入后：控件落在**当前页**（整体往右下挪 16px，再夹进画布范围，不会正好压住原有的东西）、
用到的变量缺的自动补进变量表、一套动作/绑定/组合关系原样带过来 —— **一步 `Ctrl+Z` 可整体撤销**。

## 包里有什么

```json
{
  "app": "hmi-designer", "kind": "widgets", "version": 1,
  "projectName": "玉邦6", "canvas": { "w": 1024, "h": 600 },
  "widgets":   [ /* 控件实例：几何 / 属性 / 绑定 / 动作 / 组合 */ ],
  "variables": [ /* 它们用到的变量（不带的话对面导进去就是一堆空绑定） */ ],
  "defs":      [ /* **只有自定义控件**才带：属性 schema + render 源码 + CSS */ ],
  "pageRefs":  { "pgX": { "name": "主画面", "type": "page" } }
}
```

分两层，这一点最要紧：

* **实例层**（永远带）：纯粹的数据。内置的 16 种控件对方工程里本来就有定义，
  所以这种包**一行代码都不含**，导进去只是数据搬运，没有任何风险。
* **定义层**（只有别人自己写的控件才带）：`props` 是属性面板的 schema，`renderSrc` 是**渲染函数的源码文本**。
  内置控件不带这一层（对方也有，带了反而多余）。

跳转/弹窗动作按**目标页名字**重新对上（导出时记了 `pageRefs`），对不上就清空并在报告里说一声。

## 自定义控件 = 别人的代码（唯一要当心的地方）

控件的渲染函数是**真的 JavaScript**，不是数据。所以「导入别人做的控件」=
**在你这台机器上执行别人的代码**，性质和「脚本」面板完全一样。为此：

1. **导入前把源码摊开给你看**：包里带定义时，会先弹一个确认框，逐条列出
   `类型 / 中文名 / 属性个数 / 带没带样式`，下面就是 `render` 的源码全文（超过 24 行会折叠），
   你点「知道了，导入」才注册。**只导入信得过的来源。**
2. **不带 `allowCode` 一律拒绝**：数据层（`project.importWidgetPack(pack)`）默认拒绝带定义的包，
   界面确认过才带 `{allowCode: true}` 调进去 —— 不会出现"点一下就悄悄执行了代码"。
3. **导入前先冒烟渲染一次**：`new Function` 只查语法，**不查里面引用的名字存不存在**。
   所以注册时会先用默认属性 + 假变量值把 `render` 真跑一遍（编辑态和运行态各一次）：
   跑不起来的定义**当场拒掉并回滚**（不留"半成品定义"在注册表里），原因写清楚
   （如「运行态渲染跑不起来：根本没有这个helper is not defined」）。
4. **不许覆盖内置类型**：包里带 `type: "button"` 这种和内置重名的定义 → 忽略并报告，
   内置控件一个字节都不动。
5. **没有对应类型的控件实例会被跳过**：宁可不进来，也不要在画面上留一块「渲染不出来、还点不动」的空白。

render 里能用的是**白名单里的 helper**（和内置控件用的是同一批）：

```
rutil  fmtValue  escapeHtml  varValue  stateVarOf  numberFmtOf  compareVal
parseOptions  optionIndexByValue  comboMode  contrastTextOn  fmtTime  fmtDate
dayStart  isArrayType  TIME_PRESETS  ARR_TYPES  SCALAR_NUM  splitLines  splitRow
pickTimeFmt  activeAlarms  alarmHistory  historyOfDay  alarmHistoryDay  levelOf  esc
```

所以要写自定义控件，render 里直接用 `escapeHtml(...)` / `varValue(w, vars)` 就行，**不用写 import**。
想用白名单外的东西，得先把它加进 `js/widgets/pack.js` 的 `HELPER_NAMES`。

## 自定义控件定义跟着工程走

导进来的自定义控件，它的定义会存进**工程**（`data.customWidgets`），和 PLC 配置、面板布局、
权限表、脚本一个待遇：

* 换台机器、换个浏览器打开这份**工程文件**，控件照样渲染得出来（`normalize()` 会先把定义注册进注册表）；
* 存到服务器 / 从服务器读，也一起带走；
* 自定义控件在左侧控件库里带一个紫色「**包**」角标，一眼分得清哪些不是内置的；
  导入成功后控件库会**当场重建**，新控件立刻能拖。

## 样式（CSS）怎么办

导出时按**类名约定**从已加载的样式表里挑规则：选择器里带 `.wd-<type>`（注册表自动加的外层类）
或 `.w-<type>`（作者自己写的类）的规则，都跟着包走。所以自定义控件的 CSS 建议用这两个前缀之一。

> 小知识：CSS 是从 CSSOM 的 `cssText` 取的，浏览器会规范化字面量（`#22c55e` → `rgb(34, 197, 94)`）——
> 语义完全一样，只是导出文件里的写法和你写的不完全一致。

## 边界 / 已知限制

* 只支持**控件**级（单个/一组）。整页搬运有「页面 ▸ 导出这一页…」，整工程有「工程 ▾」。
* 包里的 `variables` 是**按名 upsert**：同名变量保留你工程里的（地址不一样只提醒，不静默改）。
* 报警、脚本**不跟着控件包走**（它们是整机的，理由同单页导出）。
* 组件里用到的**公共底**不跟着走（底是页面级的东西）；要复用就把它画进一个普通控件组里导出去。
* `render` 必须是**普通函数写法**（`render(w, mode, vars) {…}` 或 `function render(…) {…}`），
  箭头函数/async 暂不支持（导入时会明确报"认不出来"，不会静默失败）。
